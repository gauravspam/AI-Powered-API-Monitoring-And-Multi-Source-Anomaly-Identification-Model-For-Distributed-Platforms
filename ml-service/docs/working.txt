Model Working Overview (Encoders + Three Models)

1) Encoders (modality-specific feature extraction)

1.1 Metric Encoder
- Implementation: [src/models/metric_encoder.py](src/models/metric_encoder.py)
- Class: [`src.models.metric_encoder.MetricEncoder`](src/models/metric_encoder.py)
- Purpose: Converts variable-length metric time series (per metric) into a fixed 128‑dim embedding suitable for downstream fusion.
- How it works:
  1) For each metric name + time series:
     - Encodes with an LSTM (bidirectional) to capture temporal dynamics.
     - Projects final hidden state to an embedding space.
     - Adds a learned semantic embedding for the metric name.
  2) Stacks embeddings from all metrics and applies multi‑head attention.
  3) Aggregates (mean) to a single fixed embedding.
- Output: Tensor shape (1, 128).

1.2 Log Encoder
- Implementation: [src/models/log_encoder.py](src/models/log_encoder.py)
- Class: [`src.models.log_encoder.LogEncoder`](src/models/log_encoder.py)
- Purpose: Converts variable-length log strings into a fixed 128‑dim embedding.
- How it works:
  1) Uses BERT (frozen) to encode each log line (CLS embedding).
  2) Projects 768‑dim BERT output to 128‑dim space.
  3) Stacks per‑log embeddings and applies multi‑head attention.
  4) Aggregates (mean) to a single embedding.
- Output: Tensor shape (1, 128).
- Pretraining pipeline is in [training/pretrain/train_log_encoder.py](training/pretrain/train_log_encoder.py).

1.3 Trace Encoder
- Implementation: [src/models/trace_encoder.py](src/models/trace_encoder.py)
- Class: [`src.models.trace_encoder.TraceEncoder`](src/models/trace_encoder.py)
- Purpose: Encodes distributed trace graphs into a fixed 128‑dim embedding.
- How it works:
  1) Builds a directed graph from spans (service topology).
  2) Extracts node features (duration, error, in/out degree).
  3) Encodes nodes via a feed‑forward encoder.
  4) Applies one‑hop message passing (neighbor aggregation).
  5) Global mean pooling and readout projection.
- Output: Tensor shape (1, 128).
- Pretraining pipeline is in [training/pretrain/train_trace_encoder.py](training/pretrain/train_trace_encoder.py).

2) Three Models (fusion + decision)

2.1 MSIF‑LSTM (Enhanced Multimodal)
- Implementation: [src/models/msif_lstm_model.py](src/models/msif_lstm_model.py)
- Class: [`src.models.msif_lstm_model.VariableInputMSIF_LSTM`](src/models/msif_lstm_model.py)
- Purpose: Uses LSTM + attention to produce anomaly probability from unified embeddings.
- Working:
  1) Accepts either (Batch, Features) or (Batch, Seq, Features).
  2) Ensures 3D input, runs Bi‑LSTM over sequence.
  3) Applies multi‑head attention across sequence.
  4) Classifier outputs sigmoid score (0–1).
- Training script (multimodal scalar features): [training/fusion/train_msif_enhanced.py](training/fusion/train_msif_enhanced.py)

2.2 PLE‑GRU (Enhanced Multimodal)
- Implementation: [src/models/ple_gru_model.py](src/models/ple_gru_model.py)
- Class: [`src.models.ple_gru_model.VariableInputPLE_GRU`](src/models/ple_gru_model.py)
- Purpose: Multi‑expert GRU model with attention fusion to estimate anomaly probability.
- Working:
  1) Accepts either (Batch, Features) or (Batch, Seq, Features).
  2) Runs multiple expert GRUs in parallel.
  3) Each expert produces a summary; outputs are fused via multi‑head attention.
  4) Classifier outputs sigmoid score (0–1).
- Training script: [training/fusion/train_ple_enhanced.py](training/fusion/train_ple_enhanced.py)

2.3 Hybrid Fusion (Final Decision)
- Implementation: [src/models/hybrid_fusion.py](src/models/hybrid_fusion.py)
- Class: [`src.models.hybrid_fusion.HybridFusion`](src/models/hybrid_fusion.py)
- Purpose: Combines MSIF‑LSTM and PLE‑GRU scores using context‑aware weighting and agreement rules.
- Working:
  1) Calculates dynamic weights using context (time, traffic).
  2) Computes agreement = 1 − |msif − ple|.
  3) If high agreement → weighted average.
     If moderate → conservative max.
     If low → conflict resolution via max.
  4) Returns final fused score + method + agreement.

3) End‑to‑End Inference Flow (Multimodal API)

- Main API for multimodal inference: [api/app_multimodal.py](api/app_multimodal.py)
- Pipeline:
  1) Input: scalar metrics/logs/traces features.
  2) Apply log1p normalization.
  3) Feed into MSIF‑LSTM and PLE‑GRU.
  4) Fuse with HybridFusion.
  5) Return final anomaly status and scores.

Notes
- The encoders produce 128‑dim modality embeddings, while the enhanced fusion scripts currently operate on 3‑dim scalar features; they can be extended to use the encoder embeddings directly.
- Encoders are pretrained using the scripts in [training/pretrain](training/pretrain).
